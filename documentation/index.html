🚀 Installation

Method 1 — Automated (Recommended)

One command does everything:

# Clone / extract the project, then:
python install.py

The installer will:

  1. Create .env from template
    Copies .env.example → .env and prompts you to review settings.
  2. Install Python dependencies
    Runs pip install -r requirements.txt automatically.
  3. Prepare the database
    Runs all Django migrations. Works with SQLite (default) or PostgreSQL.
  4. Create admin account
    Creates admin user with password admin123.
  5. Load demo data
    Populates with projects, tasks, evaluations, and notifications.
  6. Set up frontend
    Runs npm install for the Vue.js frontend.

Method 2 — Manual

Step 1 — Backend Setup

# 1. Create & activate a virtual environment
python -m venv venv
venv\Scripts\activate          # Windows
source venv/bin/activate       # macOS / Linux

# 2. Install dependencies
pip install -r requirements.txt

# 3. Create .env file
copy .env.example .env         # Windows
cp .env.example .env           # macOS / Linux

# 4. Run database migrations
python manage.py migrate

# 5. Create admin user
python manage.py createsuperuser

# 6. Load demo data (optional)
python demo_data.py

# 7. Start backend server
python manage.py runserver

Step 2 — Frontend Setup

cd frontend
npm install
npm run dev     # Development server
# or:
npm run build   # Production build → output in dist/
✅
Done! Open your browser: Frontend: http://localhost:5173  |  Backend API: http://localhost:3535  |  Admin: http://localhost:3535/admin

Setup for Local Network (LAN)

To make Sentry PM accessible to all devices on your network:

# Step 1: Find your local IP address
ipconfig          # Windows — look for IPv4 (e.g. 192.168.1.100)
hostname -I       # Linux/Mac

# Step 2: Run backend on all interfaces
python manage.py runserver 0.0.0.0:3535

# Step 3: Update .env
ALLOWED_HOSTS=192.168.1.100,localhost

# Step 4: Run frontend
cd frontend && npm run dev -- --host 0.0.0.0
✅
Any device on the same Wi-Fi can now access: http://192.168.1.100:5173 — replace the IP with your machine's IP address.

🌐 Online Deployment (Production)

To make Sentry PM accessible from anywhere on the internet, choose one of these deployment options:

Option 1 — Railway.app (Easiest, Recommended)

  1. Push code to GitHub
    Create a private repository and push the source code.
  2. Connect to Railway
    Go to railway.app → New Project → Deploy from GitHub.
  3. Add environment variables
    Set SECRET_KEY, DEBUG=False, DB_ENGINE=postgresql and Railway's auto-provisioned POSTGRES_* vars.
  4. Deploy and get your URL
    Railway provides a public URL like https://sentry-pm-xxxx.railway.app in seconds.

Option 2 — VPS (DigitalOcean / Hetzner / AWS)

# 1. Connect to your server
ssh user@your-server-ip

# 2. Install Python, Node.js, and Nginx
sudo apt update && sudo apt install python3 python3-pip nodejs npm nginx -y

# 3. Upload and install the project
git clone your-repo /var/www/sentry-pm
cd /var/www/sentry-pm && python install.py

# 4. Build frontend for production
cd frontend && npm run build

# 5. Run backend with Daphne (ASGI)
daphne -b 0.0.0.0 -p 3535 config.asgi:application &

# 6. Configure Nginx to proxy requests
# (see full Nginx config in the appendix below)

Option 3 — Render.com (Free tier available)

Render supports Python/Django apps natively. Connect your GitHub repo, set environment variables, and deploy with zero configuration.

⚠️
WebSocket requirement: Real-time features (chat, notifications) require an ASGI server (Daphne). Shared hosting that only supports WSGI will work but without real-time features.

🔗 SDK Integration — Monitor Any App

The included client_sdk.js is a drop-in JavaScript library. Add it to any web application and it will automatically send all errors, network failures, and session recordings to your Sentry PM instance.

💡
Works with any tech stack: React, Vue.js, Angular, plain HTML, WordPress, Shopify — any web app running JavaScript.

Step 1 — Add the scripts to your app's HTML

<!-- In the <head> of every page you want to monitor -->
<script src="https://cdn.jsdelivr.net/npm/rrweb@latest/dist/rrweb.min.js"></script>
<script src="https://YOUR-SENTRY-PM-URL/static/client_sdk.js"></script>

Step 2 — Initialize the SDK

<script>
  // Add this after the scripts above
  window.addEventListener('load', function() {
    Tracker.init({
      trackerUrl: 'https://YOUR-SENTRY-PM-URL',  // Your Sentry PM server URL
      project:    'My Application Name',          // Must match a project in Sentry PM
      userId:     'user_123'                       // Optional: logged-in user ID
    });
  });
</script>

That's it! What gets monitored automatically:

Event TypeHow It's CapturedWhere to See It
JavaScript ErrorsAutomatically via window.onerrorIssues → Exceptions tab
Unhandled PromisesAutomatically via unhandledrejectionIssues → Exceptions tab
Network Failures (400/500)Fetch & XHR interceptionIssues → Network Registry
Console errorsIntercepts console.error()Sent with each error report
Session Recordingrrweb records DOM changesIssues → Session Replay button
Click BreadcrumbsDOM click listenerSent with each error report

Integration Examples

React Application

// In your App.jsx or main index.jsx
import { useEffect } from 'react';

function App() {
  useEffect(() => {
    if (window.Tracker) {
      window.Tracker.init({
        trackerUrl: process.env.REACT_APP_SENTRY_PM_URL,
        project:    'My React App',
        userId:     currentUser?.id || 'guest'
      });
    }
  }, []);
}

Vue.js Application

// In main.js
app.config.errorHandler = (err) => {

How the Data Flows

Your App (Browser)
   ↓ JavaScript error occurs
   ↓ SDK captures: error + stack + last 20s session recording
   ↓ POST /api/capture/ → Sentry PM Server
      ↓ Saved to database
      ↓ Visible in Issues dashboard
      ↓ Developer clicks "Replay" → watches what user did before the crash

Manual Error Capture

You can also capture errors programmatically from your own catch blocks:

try {
  riskyOperation();
} catch (error) {
  window.Tracker?.captureException(error); // Send to Sentry PM manually
  throw error; // Re-throw if needed
}

❓ Frequently Asked Questions

Can I use SQLite instead of PostgreSQL? ▼
Yes! Open .env and set DB_ENGINE=sqlite. SQLite is the default and requires no additional setup. It's great for development and small deployments. For production on live servers, we recommend PostgreSQL for performance and concurrency.
How do I run the backend and frontend together? ▼
Open two terminal windows. In the first: python manage.py runserver. In the second: cd frontend && npm run dev. The Vue.js frontend is pre-configured to proxy API requests to localhost:3535.
How do I integrate the Error Tracking SDK into my app? ▼
Copy client_sdk.js from the project root and add it to your web app's HTML. Configure it with your Sentry PM URL and project key. The SDK automatically captures JavaScript errors, network failures, and console errors.
Does it work in Arabic (RTL) mode? ▼
Yes, fully! The platform includes complete Arabic translation and RTL layout support. Users can switch between Arabic and English from the top navigation bar. All components, animations, and layouts are designed to work in both directions.
Can I deploy this on shared hosting? ▼
The WebSocket (real-time chat/notifications) features require an ASGI server (Daphne/Uvicorn), which is not supported by traditional shared hosting. We recommend a VPS, cloud instance (DigitalOcean, AWS EC2), or platforms like Railway or Render.
How do I change the admin password? ▼
Log in as admin and go to Settings → Security & Account to change the password from the UI. Alternatively, use the command line: python manage.py changepassword admin
How do I reset the demo data? ▼
Run python reset_demo.py and type RESET when prompted. This clears all projects, tasks, and evaluations, then reloads the original demo data. User accounts are preserved.
Can I customize the color theme? ▼
Yes! In Settings → Preferences, users can choose from 6 color themes (Indigo, Emerald, Rose, Amber, Ocean, and the default Omnia). The settings are saved per-user in their profile.
Is the source code included? ▼
Yes, the complete source code for both backend (Django) and frontend (Vue.js) is included. You can customize, extend, and white-label the application for your clients.
What Python version is required? ▼
Python 3.10 or higher is required. We recommend Python 3.12 for the best performance and latest security patches. Check your version with python --version.
